# skein-api

The backend of [Skein](https://github.com/tryskein/skein), a task tracker for AI
agents and humans. It holds all business logic and data access:

- the REST API under `/api/v1`, used by the web UI;
- the MCP server at `/mcp` (Streamable HTTP), used by agents;
- the agent task-monitor API under `/agent/v1` (notification polling and the
  monitor script);
- background workers: the outbox dispatcher to NATS (live updates), Web Push,
  the stale-lock reaper, reminders, nudges, and cleanup sweeps;
- the database schema: SQL migrations, applied by the service at startup.

skein-api is internal: it has no public port. Browsers and agents reach it
through the public edge (the nginx of
[skein-frontend](https://github.com/tryskein/skein-frontend)) and
[skein-web](https://github.com/tryskein/skein-web), which forwards REST and MCP
requests here with a shared internal secret. How the three services fit
together is described in the umbrella
[README](https://github.com/tryskein/skein#readme) and
[ARCHITECTURE.md](https://github.com/tryskein/skein/blob/main/ARCHITECTURE.md).

## Stack

Go, [chi](https://github.com/go-chi/chi), [pgx](https://github.com/jackc/pgx)
with PostgreSQL + [pgvector](https://github.com/pgvector/pgvector),
[golang-migrate](https://github.com/golang-migrate/migrate),
[sqlc](https://sqlc.dev), [mcp-go](https://github.com/mark3labs/mcp-go), NATS,
S3-compatible storage (Garage, SeaweedFS, RustFS, AWS S3) for attachments, Prometheus metrics, `log/slog`. Versions are in
`src/go.mod`.

## Getting the code

skein-api is developed inside the Skein workspace: clone the umbrella repository
and the services into its `projects/` directory, as described in the umbrella
[DEVELOPMENT.md](https://github.com/tryskein/skein/blob/main/DEVELOPMENT.md).

```
skein/                    umbrella: compose files, test harnesses
└── projects/
    ├── skein-api/        this repository
    ├── skein-web/
    └── skein-frontend/
```

## Build and run

The easiest way is the whole local stack, from the top of `skein/`:

```bash
docker compose --env-file versions.env -f docker-compose.local.yml \
  -f docker-compose.local.build.yml up -d --build
```

The second `-f` is the build overlay that builds the services from `projects/`; without it the stack
runs the published images. To run only the backend and its database:

```bash
docker compose --env-file versions.env -f docker-compose.local.yml \
  -f docker-compose.local.build.yml up -d --build postgres skein-api
```

Standalone, from this repository, against a PostgreSQL that has the `pg_trgm`
and `vector` extensions (the image in `infra/postgres/` creates them):

```bash
cd src
go build -o ./bin/api ./cmd/api/
DATABASE_URL='postgres://skein:<password>@localhost:5432/skein?sslmode=disable' \
SKEIN_INTERNAL_SECRET='<at least 16 characters>' \
SKEIN_AGENT_PUBLIC_URL='http://localhost:5100' \
./bin/api
```

Then:

```bash
curl -i http://localhost:5100/healthz   # liveness, always 200
curl -i http://localhost:5100/ready     # readiness: database (and the S3 storage when enabled)
curl    http://localhost:5100/metrics   # Prometheus metrics
```

The container image is built from the `Dockerfile` at the repository root
(`docker build -t skein-api .`). Released images are published as
`ghcr.io/tryskein/skein-api`.

## Configuration

Configuration comes only from environment variables. Every variable — purpose,
whether it is required, default, format, and what happens when it is unset — is
documented in [`docs/env-reference.md`](docs/env-reference.md). Three are
required and the service does not start without them: `DATABASE_URL`,
`SKEIN_INTERNAL_SECRET`, `SKEIN_AGENT_PUBLIC_URL`.

## Database migrations

Migrations live in `src/migrations/` as `000NNN_name.up.sql` /
`000NNN_name.down.sql`. The service applies pending migrations at startup,
before it opens its port; if a migration fails, the process exits. Several
replicas starting at once are safe — golang-migrate takes an advisory lock.

The image also contains the `migrate` CLI and the SQL files in `/app/migrations`:

```bash
docker run --rm --entrypoint migrate <image>:<tag> \
  -path /app/migrations -database "postgres://user:pass@host:5432/db?sslmode=disable" up
```

A released migration is never edited; changes go into a new one. What to check
before a release that carries migrations (reversible or not, when all instances
must stop, backups) is in the umbrella
[DEPLOYMENT-NOTES.md](https://github.com/tryskein/skein/blob/main/DEPLOYMENT-NOTES.md).

Typed query code is generated by sqlc into `src/internal/storage/generated/` and
committed, so a clone builds without sqlc. After changing migrations or
`src/internal/storage/queries/`, run `cd src && sqlc generate`.

## API documentation

Handlers carry [swag](https://github.com/swaggo/swag) annotations. The OpenAPI
document is generated, not committed:

```bash
cd src
go tool swag init -g cmd/api/main.go -o docs/ --exclude internal/operator
go tool swag init -g server.go -d internal/operator --instanceName operator -o docs/operator
```

The second command documents the separate operator API, which listens on its
own port with its own key.

## Tests

```bash
cd src && go test -count=1 ./...          # unit tests (database tests skip)
./scripts/integration-test.sh             # from the top of skein/: integration tests, needs docker
```

All test kinds, narrowed runs, prerequisites and pitfalls are in the
`## Testing` section of [`CLAUDE.md`](CLAUDE.md).

## Known limitations

The catalogue of theme roles in `src/internal/themes/` is a hand-maintained
mirror of the registry in skein-frontend. This repository alone cannot check
it; in the workspace, `./scripts/check-theme-mirror.sh` (from the top of
`skein/`) compares the two sides and fails on any difference.
